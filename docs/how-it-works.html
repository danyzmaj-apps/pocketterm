PocketTerm: how it works

Your sessions always live on your computer, and so does the small PocketTerm server that connects your phone to it. The phone reaches it over your own Tailscale network, and everything that matters is end-to-end encrypted between the computer and the phone.

sealed with the computer's key (only the computer and your phones can read) stays on the computer push (opt-in), still sealed

What happens, step by step

  1. Setup wizard checks TailscaleInstalled, running, signed in, HTTPS certificates on, port 443 free. Each row turns green on its own; buttons install or open things only after you confirm.
  2. The desktop app starts the built-in serverIt listens on 127.0.0.1 only, so nothing on your Wi-Fi or the internet can reach it directly.
  3. Tailscale publishes it privatelytailscale serve gives it an HTTPS address like https://your-computer.tail1234.ts.net that only devices signed in to your Tailscale can open.
  4. You scan the QR code with your phoneThe code carries the server address, a one-time pairing code and this computer's encryption key. It never goes through any server.
  5. The phone connects through its Tailscale appFrom anywhere: home Wi-Fi, mobile data, a café. Tailscale makes a direct encrypted tunnel to your computer. If your tailnet has device approval on, approve the phone in Tailscale's admin console first.
  6. Everything inside is sealed againConversations, screens, prompts, images and files are encrypted with the computer's key before they leave, so even the server only passes ciphertext.
sealed with each computer's own key stays on the first computer

What happens, step by step

  1. On the first computer: Add a computer…Settings → Account shows a setup link like pocketterm://setup?url=https://your-computer.tail1234.ts.net&setup=…. It lets a computer sign in, not read sessions; show it only to your own computers.
  2. On the new computer: Join another computer's PocketTerm…In the setup, paste the link. Tailscale must be signed in to the same account. Release builds accept only *.ts.net addresses.
  3. The new computer signs in to the first one's serverIt doesn't run a server of its own. The first computer has to be awake for both.
  4. Scan the new computer's QR codeEach computer has its own key, so your phone scans each one's code once. Then pick a computer at the top of the phone's list.

Sealed end to end

Conversations, prompts, screens, keys you press, images, files and their names, and notification text.

Visible to the server

Your device list, computer names, pairing codes (hashed), push tokens, and when devices talk. Images and files wait there sealed until the computer fetches them, at most an hour.

Push relay (only if you turn notifications on)

Run by Danijel Lovric on his server in Germany. Receives requests sealed to its own key, forwards the still-sealed notification to Apple or Google and stores nothing. The relay and Apple or Google see an encrypted message, a push token and when it was sent, never which computer or session it is about.

Lock Screen updates (iPhone)

When you follow a session, iOS shows its state on the Lock Screen: working, needs you, or finished. Apple doesn't let apps decrypt these updates, so this state travels unencrypted. It never includes any text from your sessions, and it carries no names, folders or ids.

Lost a phone?

Settings → Account: Sign out… next to it ends its sign-in. Settings → Phone → Reset key: the computer makes a new key; every phone you keep scans again; the old key opens nothing new.

Links from outside

A link opened from a message or website can never install a key. Only the in-app scanner can.
