PocketTerm: how the three setups work

Your sessions always live on your computer. The only question is where the small PocketTerm server runs that connects your phone to it. In every setup, everything that matters is end-to-end encrypted between the computer and the phone.

sealed with the computer's key (only the computer and your phones can read) stays on the computer push (opt-in), still sealed

What happens, step by step

  1. Setup wizard checks TailscaleInstalled, running, signed in, HTTPS certificates on. Each row turns green on its own; buttons install or open things only after you confirm.
  2. The desktop app starts its own serverIt listens on 127.0.0.1 only, so nothing on your Wi-Fi or the internet can reach it directly.
  3. Tailscale publishes it privatelytailscale serve gives it an HTTPS address like https://your-mac.tail1234.ts.net that only devices signed in to your Tailscale can open.
  4. You scan the QR code with your phoneThe code carries the server address, a one-time pairing code and this computer's encryption key. It never goes through any server.
  5. The phone connects through its Tailscale appFrom anywhere: home Wi-Fi, mobile data, a café. Tailscale makes a direct encrypted tunnel to your Mac.
  6. Everything inside is sealed againConversations, screens, prompts, images and files are encrypted with the computer's key before they leave, so even the server only passes ciphertext.

What happens, step by step

  1. The wizard asks for your server's addressAn IP like 203.0.113.7 becomes the free name 203-0-113-7.sslip.io; a domain stays as typed.
  2. You run four commands on the serverInstall Docker, download PocketTerm's compose file (pinned to your app version), start it, print the setup link. Each has a Copy button.
  3. Caddy gets an HTTPS certificate by itselfPorts 80 and 443 must be open. The wizard watches: name resolves → HTTPS answers → server healthy.
  4. You paste the setup linkThis computer signs in to your server. Other computers can join with the same kind of link.
  5. You scan the computer's QR code with your phoneSame as the other setup: address, pairing code, and the computer's key, straight from screen to camera.
  6. Both connect out to the serverThe computer and the phone only make outgoing connections, so nothing at home needs to be reachable, and no Tailscale is needed.

What happens, step by step

  1. You paste a Supabase access tokenIt covers your whole Supabase organization. PocketTerm uses it only during setup and never stores it: best, an organization of its own for PocketTerm, and delete the token afterwards.
  2. You pick the organization and a regionPocketTerm creates a free project named PocketTerm there (or updates the one that already has PocketTerm on it). Supabase, in that region, holds the server's metadata.
  3. The wizard sets the project upDatabase, live channel key, the pocketterm server function, then this computer signs in. Other computers join with a setup link from Add a computer…, no token needed.
  4. You scan the computer's QR code with your phoneSame as the other setups: address, pairing code, and the computer's key, straight from screen to camera.
  5. Both connect out to supabase.coThe function answers the same requests as the PocketTerm server; the live channel runs over Supabase Realtime with a 10-minute token per device. Both pass on ciphertext only. No Tailscale, nothing reachable at home.
  6. Free projects pauseAfter about a week without use. Restore it at supabase.com/dashboard. The free plan allows 2 active projects per account.

Sealed end to end

Conversations, prompts, screens, keys you press, images, files and their names, and notification text.

Visible to the server

Your device list, computer names, pairing codes (hashed), push tokens, and when devices talk. Images and files wait there sealed until the computer fetches them, at most an hour.

Push relay (only if you turn notifications on)

Run by Danijel Lovric on his server in Germany. Receives requests sealed to its own key, forwards the still-sealed notification to Apple or Google and stores nothing. The relay and Apple or Google see an encrypted message, a push token and when it was sent, never which computer or session it is about.

Lock Screen updates (iPhone)

When you follow a session, iOS shows its state on the Lock Screen: working, needs you, or finished. Apple doesn't let apps decrypt these updates, so this state travels unencrypted. It never includes any text from your sessions, and it carries no names, folders or ids.

Lost a phone?

Settings → Phone → Reset key. The computer makes a new key; every phone scans again; the old key opens nothing new.

Links from outside

A link opened from a message or website can never install a key. Only the in-app scanner can.
